# OpenStrap: Provider SDK / plugin contract grill

Создано: 2026-07-27

Статус: open

Источник: grill-сессия по [issue #29](https://github.com/yardencom/openstrap/issues/29). Ветка `Provider SDK / plugin contract` из `product-grill-open-branches.md`.

Закрыта часть ветки: границы transport, владение сбором фактов, владение секретами, рантайм. Не закрыты: capabilities провайдера, lifecycle цели, форма команды `create`.

## Решения

1. **Кто выполняет команду на машине.** Решение: обязанность transport. Transport - это соединение и операции через него: прочитать файл, выполнить команду, сходить по сети.

2. **Что transport не включает.** Решение: печать прогресса в терминал и окружение процесса openstrap (`stateHome`, `PATH` процесса) транспортом не являются и в порт не входят. Порт transport не отдает производных данных: определение ОС не является операцией transport, потому что это работа facts.

3. **Transport-плагин и facts.** Решение: `@openstrap/ssh` регистрирует только transport и facts backend не регистрирует. Плагин про SSH - это про SSH, не про факты.

4. **Единица изменчивости в сборе фактов.** Решение: изменчивость по ОС, не по transport. Один facts-модуль с per-OS сборщиками работает через transport. Хост не является исключением: хост - это локальный transport, реализованный системными вызовами.

5. **Ответственность модуля Facts.** Решение: модуль facts и собирает, и предоставляет. Разделение на «сборщик» и «результат» отдельными модулями не вводится: модуль должен быть самодостаточным и тестируемым.

6. **Точка входа сбора.** Решение: сбор не выполняется в конструкторе. Модуль facts создает инстанс и предоставляет API для работы с ним. Следствие: сбор может ждать сеть, что обязательно для сбора с guest через SSH.

7. **`target.type` в v1.** Решение: закрытый перечень `vm`, `container`, `host`. Значение `machine` недопустимо. Принцип тот же, что у `scope` в решении 34 `fact-context-schema-grill`: в v1 закрыто, расширяемо позже.

8. **Где живут вычисленные значения.** Решение: lock-файл содержит только переносимое между людьми и машинами - разрешенный образ, sha, формат, boot mode, версии плагинов. Локальное состояние - выделенные порты, id ресурсов провайдера, прогоны, снимки фактов - живет только в state store. Пересечения нет, lock-файл не является отчетом из базы.

9. **Владение секретами.** Решение: secret store - порт ядра. Ядро генерирует и хранит приватный ключ, плагин получает ссылку, не значение. Плагин transport своим keychain не владеет.

10. **Рантайм и единый бинарь.** Решение: Node. Сборка единого бинаря через `@yao-pkg/pkg`, встроенный SQLite через `node:sqlite`. Bun не берется: его единственное преимущество - `bun build --compile` - уже закрыто через `pkg`, а цена - переезд работающего кода и тестов.

11. **Декомпозиция вехи.** Решение: issue #29 остается описанием вехи. Работа идет отдельными issue по этапам: ядро, `ssh`, `utm`, `create`, `connect`. Существующие #12, #14, #20 переиспользуются, а не дублируются.

12. **Перевод facts на transport входит в веху 1.** Решение: отдельный пункт этапа A - facts-модуль собирает через порты transport. Идет после портов и до `create`. Без него критерии вехи 1 про подтвержденные проверки на guest недостижимы.

## Что эти решения меняют в issue #29

- этап B: «Регистрирует транспорт и сбор фактов для секции `transports.ssh`» - вычеркивается (решение 3).
- этап A4: «перенести `SystemAPI` без изменений, пять портов» - неверно. `output` и `environment` процесса в transport не переезжают (решение 2).
- `FactsBackend.capabilities.transports` теряет смысл: бэкенд больше не привязан к transport (решения 1, 4).
- обоснование имени плагина через «Docker закроет Provider, Transport и Facts одновременно» переписывается на Provider + Transport (решение 3).
- `openstrap-ssh` коммит 3 `feat: store private key in system keychain` переезжает в ядро (решение 9).
- `examples/openstrap/local-run.yaml` и хардкод в `FactsCollectCommand` правятся с `type: machine` (решение 7).
