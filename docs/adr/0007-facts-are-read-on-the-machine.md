# Факты собираются на самой машине, а не о ней

Факты читаются через API машины и на самой машине. Хост читается в текущем процессе; машина, до которой openstrap дотягивается через transport, читается тем же кодом, который openstrap туда доставляет как самодостаточный исполняемый файл. Transport - канал доставки и запуска, а не источник фактов.

Отсюда `Facts` - единственный вход в модуль: `new Facts()` читает машину, на которой openstrap запущен, `new Facts(transport)` - машину на другом конце. Локального transport не существует: если канала нет, читать нужно здесь и сейчас.

## Considered Options

**Разбирать вывод программ через transport.** Отклонено: это вторая реализация того же самого. Хост читался бы через `node:os`, гость - через `ps`/`systemctl`/`df`, и две реализации расходятся. Это уже было сделано и уже сломалось: снимок гостя оказался несравним со снимком хоста, а `ps -axo comm` на BSD обрезал имя процесса до 16 символов, из-за чего 678 из 680 процессов назывались `/System/Library/`. Плюс `wmic` - удалённая программа в Windows 11, то есть путь без будущего.

**Читать `/proc` и `/sys` гостя через `FileSystemAPI`.** Отклонено: чисто по API и без доставки чего-либо, но на macOS нет `/proc`, а без него список процессов не получить никак. Модуль перестал бы работать одинаково для хост/гость - ровно то ограничение, которое требовалось убрать.

**osquery как facts backend плагина.** Отклонено как основной механизм: требует установки на цель. Чтение машины не должно её менять.

## Consequences

`FactsBackend` как порт плагина удалён вместе с реестром, `--facts-backend`, `openstrap.config.mjs → facts.backend` и плагином `openstrap:core`. Оговорка ADR 0002 - «порт остаётся оправданным для принципиально другого механизма сбора» - не выдержала требования единственного входа: пока CLI выбирает бэкенд, входов два. Второй реализации не существует, а порт под гипотетическую реализацию - это порт, который никто не проверяет.

Агент собирается `esbuild` + `@yao-pkg/pkg` (ADR 0001) в `dist/agent/openstrap-facts-<os>-<arch>`, `npm run agent:build`. Кросс-сборка идёт с `--no-bytecode`: кэш байткода V8 валиден только для того V8, который его создал, и цель отвергает его при старте. Цена - 66 МБ на архитектуру; файл называется по sha256 своего содержимого, поэтому неизменённый агент не отправляется дважды, а изменённый нельзя спутать со старым.

Какая машина на другом конце, определяется чтением заголовка `/bin/sh`: ELF против Mach-O даёт ОС, `e_machine`/`cputype` - архитектуру. Это не факт и в снимок не попадает - это выбор бинаря. Читается файл, а не запускается `uname`, потому что до доставки агента запускать на цели нечего.

Два исключения из «только API» названы в коде там, где сделаны. Пароль для `sudo`: ни один API не отвечает, работает ли `sudo` без пароля, потому что единственное доказательство - что он сработал. И программы, которые объявил сам вызывающий в facts definition: openstrap не решает запустить программу, он запускает ровно объявленное.

Служба считается present, когда она запущена. Установленная, но остановленная служба читается как absent - это самое сильное утверждение, верное на всех платформах: launchd не даёт спросить о существовании label, не спрашивая о загруженности. Поле `running` несёт тот же ответ явно, поэтому требование можно написать в любую сторону.

Секции `users`, `groups`, `sessions` facts definition объявить позволяет, а чтение не отвечает. Они перечислены в `DeclaredFacts.unread` и печатаются как «Declared but not read», потому что определение, которое молча собирает восемь секций из десяти, хуже определения, которое собирает восемь и говорит об этом.
