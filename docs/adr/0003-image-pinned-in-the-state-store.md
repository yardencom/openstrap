# Образ закреплен в state store, отдельного lock-файла нет

Заменяет прежнее решение: `openstrap.lock.yaml` в репозитории отменен. Образ, из которого сделана цель - url, sha, платформа, архитектура, формат, boot mode, - записывается в state store, в таблицу `pinned_image`, рядом с портами, id ресурсов провайдера, прогонами и снимками фактов. Отдельного файла в проекте openstrap не создает вообще.

`create` читает пин **до** того, как спрашивает провайдера, и передает его провайдеру: тот обязан вернуть именно этот файл, а не то, во что имя разрешается сегодня. Пришедшее все равно сверяется с пином - провайдер это плагин, а правило, которое держится только пока каждый плагин его соблюдает, не правило. Расхождение sha или смена `image` в блюпринте - ошибка `PinnedImageChangedError`, а не новый пин. Сдвинуть пин можно только явно: `openstrap create vm <target> --repin`.

## Considered Options

Прежнее решение - lock-файл в репозитории с тем, что одинаково у всех, кто его склонирует. Отклонено по факту: его никто не читал. `LockFile.read()` вызывался только изнутри `record()`, чтобы не потерять остальные цели при записи, и в собственных тестах. `create` каждый раз заново спрашивал `resolveImage({ name: "ubuntu:24.04" })`, брал то, что провайдер выдал сегодня, и перезаписывал файл. То есть файл фиксировал прошлое и не влиял ни на одно решение - это лог, а не лок.

Оставить его в проекте и научить `create` читать - рассматривалось и отклонено. Пин говорит, из чего собрана машина **здесь**: у того, кто склонировал репозиторий, не собрано ничего, а sha в его файле относится к машине, которой у него нет. Общее между людьми - это блюпринт: имя образа, размер, требования. Что из имени получилось - свойство машины, а машины машинно-локальны.

Держать пин отдельным YAML в домашней директории тоже отклонено: это второе место для машинно-локального состояния рядом с базой, которая уже хранит то же самое про ту же цель.

## Consequences

`src/LockFile` удален, `openstrap.lock.yaml` удален из репозитория, `pluginVersions` в `CreateCommand` удалены - они существовали только ради этого файла.

`ImageRequest` в контракте плагинов получает необязательное поле `pinned: { url, sha256 }`. Провайдер, которому его передали, качает этот файл и сверяет с этой суммой; подпись публикатора при этом не проверяется, потому что публикатор не подписывает образ, который уже заменил. `@openstrap/utm` сообщает об этом честно: `signature: "pinned"`, а не `"verified"` - это разные обещания.

Воспроизводимость перестает быть свойством репозитория и становится свойством машины: тот, кто склонировал проект, получит `ubuntu:24.04` в его сегодняшнем виде и с этого момента будет закреплен на нем. Общей между людьми воспроизводимости у openstrap теперь нет, и если она понадобится - это отдельное решение о том, что именно люди делят: пин в блюпринте, а не производный файл рядом с ним.
