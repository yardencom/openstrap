# Доступ к гостю UTM - через проброшенный порт

Провайдер UTM настраивает сетевой интерфейс в режиме `emulated` с пробросом порта на `localhost` хоста и подключается по SSH туда. Это возвращает issue #29 к исходному замыслу: бэкенд `qemu` выбран ради проброса порта, и проброс порта существует.

## Отменяет предыдущую версию этого ADR

Первая редакция предписывала доступ по адресу из `utmctl ip-address`, потому что ручная проверка показала, будто проброс порта через scripting недоступен. Проверка была ошибочной: не резолвился перечислитель `protocol:TCP`, а ошибка `-1700` указывала на всю запись целиком, из-за чего непринятое одно поле выглядело как непринятая коллекция. С сырой константой `«constant ****TcPp»` проброс ставится и попадает в `config.plist`. Разбор - в `docs/wiki/grill/utm-scripting-probe.md`.

## Considered Options

Доступ по IP гостя из `utmctl ip-address` остается рабочим запасным путем, но основным не становится: адрес выдается DHCP и меняется между загрузками, а сам вызов отвечает через QEMU guest agent, которого в облачном образе Ubuntu нет - его пришлось бы ставить через cloud-init только ради получения адреса.

Правка `config.plist` внутри пакета `.utm` не нужна: официальный API покрывает и диски, и сеть.

## Consequences

Endpoint машины стабилен: `127.0.0.1:<выделенный порт>`. Порт выделяет и резервирует openstrap, поэтому таблица `allocated_port` в state store используется по назначению, а путь `create` обязан занять порт до создания машины и освободить при удалении.

Гостю не нужен QEMU guest agent для того, чтобы стать доступным. Ожидание сводится к ожиданию sshd, а не агента.

Сетевой интерфейс обязан быть в режиме `emulated`. В режиме `shared`, который UTM ставит по умолчанию, проброса порта нет.

Провайдер строит команды AppleScript с сырыми кодами перечислителей из `UTM.sdef`, а не с их именами: имена не резолвятся ни в AppleScript, ни в JXA.

Кеш образов провайдера живет внутри контейнера песочницы UTM, иначе подключение диска падает с «файла не существует» на существующем файле.

Провайдер открывает окно UTM перед любой мутирующей командой: пока окон ноль, scripting отвечает `-2700`.
